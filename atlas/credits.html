Sources, Licences & Copyright

ATLAS is built to be copyright-clean. Everything it renders is either public domain, permissively licensed with attribution, or original work written for this project. Nothing copyrighted is reproduced — where richer material exists, ATLAS links to the source instead of copying it.

3. The city dossiers — original text

All prose in the five dossiers (Mumbai, Rome, Cairo, Tokyo, Mexico City) was written for this project. It summarises well-established public history in original wording — no encyclopaedia entries, books or articles are copied. Every dossier ends with links to credible primary and reference sources (UNESCO, national governments, Encyclopædia Britannica, the World History Encyclopedia) so readers can verify the facts and read further at the source.

Linking to a website is not copyright infringement. Reproducing its text would be — so ATLAS never does. Photographs of the cities are deliberately omitted to avoid image copyright. When you select a city, its holographic view is a procedural, stylised abstraction generated in code (three.js) — not a real map or a photograph of any building — so it carries no geodata or image licence at all.

4. Accuracy notes

  • Dates for very ancient or legendary events (e.g. Rome’s 753 BC founding, the Aztec 1325 founding) are traditional and debated among historians; the text flags this.
  • City populations depend on definition (city proper vs. metropolitan area) and census year; ATLAS states which it uses and gives ranges where sources differ.

5. The login system & your credentials

The login is a gate, not real security. ATLAS is a static website with no server, so the check runs in your own browser. To keep raw passwords out of the page source, only SHA-256 hashes of each credential are stored in js/auth.js — but a determined person can still bypass any client-side gate. Never place anything genuinely sensitive behind it.

The human-readable list of the built-in accounts is stored, at your request, in a local Excel file: WorldGlobe/docs/atlas_logins.xlsx. Keep that file private and do not commit it to any public repository. To change or add built-in accounts, update the hashes in js/auth.js (the file explains how) and mirror the change in the spreadsheet.

Sign-up (self-registration). Because there is no server, a new account created with the Sign up tab is saved only in the visitor's own browser (localStorage, under the key atlas.users). It therefore works on that one device/browser and is not shared with anyone else. Only a SHA-256 hash of the password is stored, never the password itself — but it is still a client-side gate, not secure server authentication. Clearing the browser's site data removes any self-registered accounts.

6. Reuse of the parent WorldGlobe project

ATLAS reuses the already-vendored three.js and the already-downloaded NASA/GEBCO textures from the parent WorldGlobe project via relative paths (../vendor/, ../textures/). Those assets carry the licences listed above. The full provenance audit for the parent project lives in ../docs/SOURCES.md.
